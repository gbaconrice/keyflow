# 評価基準と結果

「文字が入力できる」だけでなく、毎日の入力で困らないかを測る。
Apple標準キーボード・Simejiとも同じ手順で比べられるよう、手順を固定する。

**比べていない項目について、推測で優劣を書かない。** 計測していないものは「未計測」と書く。

## 評価項目

### A. 入力の正確さ（実機）

| ID | 項目 | 手順 | 指標 |
|---|---|---|---|
| A1 | フリックの誤判定 | 下の「課題文」をフリックだけで3回入力する | 誤った文字の数／総文字数 |
| A2 | 隣のキーの誤タップ | A1と同じ | 隣のキーの文字になった数 |
| A3 | 速打ちでの欠落・順序の入れ替わり | 両手の親指で「ありがとうございます」を最速で10回 | 欠落・入れ替わりの回数 |
| A4 | 片手での打ちやすさ | 片手モード（KeyFlow）／標準の片手キーボードで課題文を入力 | 誤入力数、主観評価（5段階） |

課題文（50字）: 「明日の会議は十時からです。資料は共有フォルダに入れておきました。よろしくお願いします。」

## 結果

### KeyFlow（自動計測, 2026-10-22）

環境: Linux（x86_64の仮想マシン）、Swift 6.3.3、AzooKeyKanaKanjiConverter main@04ce2ec。
iPhoneでの数値ではない。CPUが異なるため、時間は目安。

**B1・B2 変換精度（130文）**

| 分類 | 件数 | 1位 | 3位以内 | 10位以内 | 1回学習後に1位 |
|---|---|---|---|---|---|
| 一般文 | 30 | 73% | 83% | 93% | 93% |
| 口語・チャット | 25 | 80% | 92% | 100% | 100% |
| ゲーム用語 | 20 | 90% | 100% | 100% | 100% |
| 英数字混じり | 21 | 90% | 90% | 90% | 90% |
| 固有名詞 | 20 | 100% | 100% | 100% | 100% |
| ビジネス | 14 | 100% | 100% | 100% | 100% |
| **全体** | 130 | **87%** | **93%** | **97%** | **97%** |

10月21日（補正なし, 124文）は1位85%。10月22日に「数字・何＋じ」の補正（docs/DESIGN.md）を入れ、
英数字混じりの文を6文追加した（「時」が正しい3文、「次」が正しい3文）。補正後、英数字混じりは81%→90%、一般文は70%→73%。

正解は1つの表記に限っていないが、「晩ごはん／晩ご飯」「あとで／後で」のように表記の好みで外れた例も含む。
1位にならなかった主な例:
- 同音異義語の文脈判断（「こうえんをさんぽ」→「公演を散歩」、「はしのはしをはしる」）。辞書ベースの変換の限界。
- 「かんじへんかん」→「感じ返還」（正解は4位）。
- 数字＋「ばん」（「バス2晩のりば」）。「2晩泊まる」もあるため補正していない。1回選べば学習で直る。

**C1 応答時間（1打鍵ごとの変換, 1,346回）**
- 平均 2.4 ms、中央値 1.8 ms、95%点 5.3 ms、最大 23.5 ms（長い文の最後の数文字。仮想マシンの揺れで1回だけ300 ms台が出たことがある）
- 評価プロセス全体の最大メモリ: 51.9 MB（130文を変換して辞書を読み込んだ後。iOSでの値ではない）
- 10月22日: エンジンが1打鍵ごとに180〜350件の候補を返していたのを80件までにした。平均3.2 ms→2.4 ms、正解率は変わらず

1位にしない補正（10月22日）: 「つく」→「作」のように文の終わりに来られない形で終わる候補を、同じ長さの自然な候補より下げる。130文の正解率は変わらず（「4じごろつく」の1位が「4時ごろ作」から「4時ごろつく」になった）。

**エンジンのバージョン比較（B1, 予測なしの完全一致変換）**

| | 1位 | 3位以内 | 10位以内 |
|---|---|---|---|
| v0.11.2（2026-04） | 81% | 94% | 98% |
| main@04ce2ec（2026-10） | 85% | 94% | 98% |

### シミュレーターでの自動確認（iOS 26.2, GitHub Actions）

iPhoneの実機ではない。キーボード拡張をシミュレーターのシステムキーボードとして登録し、UIテストで操作した。

- 入力・変換・確定、入力中の入力欄タップ（重複・消失なし）、ダークモード、横画面、ローマ字入力、英単語の候補: UIテストで確認
- キーボード拡張のメモリ（vmmapのPhysical footprint、4つのテストを続けて実行）:
  - 10月22日（候補の上限なし）: 表示直後 約40〜45 MB、最大 約90 MB。ヒープに候補セルが867個残っていた（候補が数百件あり、そのすべてにセルを作っていた）
  - 候補を80件までにした後: 表示直後 約42 MB、最大 約68 MB。ヒープは35 MB→27 MB、候補セルは240個
  - シミュレーターの値には、実機では共有されるシステムライブラリの分（数十MB）が含まれる。実機の値は実機で確かめる

### 実機での評価

**未計測。** A・B3・C2〜C4・D・E は、iPhoneにインストールしてから行う。

### Apple標準キーボード・Simejiとの比較

**未比較。** 同じ手順（A1〜A4、B3、C3、D1〜D3）で計測するまで、優劣は判断しない。

## 計測の再現方法

```bash
cd Packages/KeyFlowKit
swift build -c release --product KeyFlowEval
.build/release/KeyFlowEval ../../eval/corpus.tsv
```

GitHub Actionsでは毎回この評価を実行し、結果を実行結果の概要（Summary）と成果物 `eval-report` に残す。
